    Charter of the autonomous program — Cielo-Eventi¶

    Every routine session reads this file in full. It is the contract between the PO (Francesco Pacella) and the autonomous researcher. It has one purpose: run the pre-registered study through to its answer, positive or null, without needing the PO.

    0. The rule above all others¶

    Protocol v0.4 is frozen (study/FREEZE.md). The program does not look for significance: it executes a fixed design. A null result is a result. A primary analysis is never re-run because the result is unwelcome, a choice is never changed after seeing a number, and no confirmatory analysis is ever added. If a situation is not covered, the rule in § 4 applies.

    0.1 Language¶

    Everything the program writes is in English: journal entries, the index, STATE.json, results, code comments, commit messages, docs and reports. The frozen files stay as they were frozen, in Italian, and they remain the authoritative text. Their English translations sit next to them: docs/protocol/PROTOCOL-v0.3.en.md, docs/protocol/AMENDMENTS.en.md and study/protocol-v0.4.en.md. If a translation and a frozen original disagree, the original wins and the translation gets fixed. docs/protocol/PROTOCOL-v0.3.md stays in Italian, identical to the oracle's copy. The Italian original of docs/SPEC-V.md is in git history.

    1. Start of every session (always, in this order)¶

    1. git pull --rebase.
    2. scripts/verify_freeze.sh. If it fails: do nothing else. Write the journal entry with outcome: BLOCKED — freeze violated, set blocked in program/STATE.json, commit, push, stop.
    3. Read program/STATE.json, program/PLAN.md and the last 3 entries in journal/.
    4. Set up the tools needed for today's step (see program/SETUP.md). Install nothing else.

    2. One unit of work per session¶

    • Execute the next step given by STATE.json → next. One. Do not skip steps of the plan.
    • Budget: about 40 minutes of actual work. After 40 minutes start nothing new: finish what you have in hand, save, close. Long jobs (GDELT download, full Phase 0 runs) are done in resumable chunks with a cursor in STATE.json.
    • Prefer commands that write to files and logs over commands that print a lot.
    • If today's step finishes early, you may move on to the next one only if it stays in the same phase and within the budget.

    3. Things the program never does¶

    • Modify a frozen file (study/ except the .en.md translations, data/split/, the pre-freeze part of docs/protocol/AMENDMENTS.md, oracle/).
    • Compute any statistic that involves sky and validation or prospective outcomes before the plan allows it (Phases 4 and 6). The code prevents it (set guard); do not get around it.
    • Use one set's y inside the analysis of another set (amendment #24).
    • Put names of bodies, aspects, houses or signs in results/ or in numeric outputs (V3). scripts/check-contract.sh must pass before every commit.
    • Spend money, create accounts, publish, send messages or emails (the weekly message is sent by another routine), push to repositories other than this one, modify the routines.
    • Touch oracle/ (the frozen oracle) or regenerate the fixtures.
    • Modify program/CHARTER.md or program/routines/: they are the program's configuration, and only the PO changes them.
    • Make up a number. If a command fails, the journal says so, with the error.

    4. Unforeseen decisions¶

    When a choice is needed that the protocol and the plan do not cover:

    1. Look for the answer in this order: study/protocol-v0.4.json, docs/protocol/AMENDMENTS.md, docs/SPEC-V.md, docs/PHASE2.md, docs/protocol/PROTOCOL-v0.3.md (each with its .en translation where one exists).
    2. If it is not there, choose the most conservative option (fewest false positives), then the simplest.
    3. Write the decision in the journal before running the analysis that depends on it, with the reason.
    4. If the decision changes what a confirmatory analysis estimates, do not make it: it is a post-freeze amendment, which is forbidden on the primaries. Record the problem as blocked (needs the PO) and carry on with a step that does not depend on it.
    5. Implementation details that do not change the estimate (a file format, a numerically equivalent algorithm) just go in the journal.

    5. End of every session (always)¶

    1. Journal entry journal/YYYY-MM-DD-HHMM.md following journal/TEMPLATE.md. Honest: what you did, what worked, what did not, the numbers with their file, the decisions. The duration is the real one, from the session's start and end times.
    2. One row in journal/INDEX.md.
    3. program/STATE.json updated: stage, next, cursors, blocked, last_session.
    4. scripts/check-contract.sh and, if you touched engine/, the tests of the mundane module.
    5. Commit with an English message that says what changed and why, then git push. If the push fails because of divergence: git pull --rebase and retry. Never --force.

    6. Blocked¶

    If a step cannot proceed (network denied, missing data, a choice that belongs to the PO): STATE.json → blocked = {since, reason, needs} with a clear sentence on what is needed. Then, if the plan has an independent step, do that; otherwise close the session with only the journal entry. The Friday report flags it to the PO.

    7. When the program ends¶

    After the Phase 6 report (docs/REPORT.md), STATE.json → stage = "done". Later sessions check the freeze, write a "nothing to do" row in the index and close, without spending anything else.
