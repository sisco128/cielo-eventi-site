    Plan of the autonomous program¶

    Every step has a done criterion. STATE.json → next points at the current step. Steps run in order; an [independent] step may be brought forward when the current one is blocked. The reference protocol is study/protocol-v0.4.json (frozen on 2026-10-27).

    S0 — Cloud environment¶

    S0.1 Check tools and network as in program/SETUP.md: Python venv, pnpm install, ephemerides for the mundane profile, and the tests of the mundane module (unit + oracle golden). Done when: the tests pass in the cloud and the journal reports the maximum deviation of the § 6.1 gate (expected 2.63″). If a host is denied → blocked.

    S1 — Data extraction (no sky)¶

    Outputs under data/events/, each with a MANIFEST.json: source, extraction date, rows, SHA-256 of what was downloaded or of the file produced. No bulky raw data in the repo: only the daily series and, for USGS, the event list.

    S1.1 USGS [independent]. Earthquakes M ≥ 5.5 from 1990-01-01 to 2026-10-26, in yearly windows (FDSN API, format=csv, eventtype=earthquake). Outputs: data/events/usgs/events.csv (time_utc, lat, lon, depth_km, mag) and data/events/usgs/daily.csv (date, n), zero days included. Done when: both files and the manifest exist and the yearly counts are in the journal.

    S1.2 Markets [independent]. S&P 500 (^GSPC, Yahoo: amendment #28), from the first date ≥ 1928-01-01 to 2026-10-26. Output data/events/markets/daily.csv (date, close, y) with y = |ln(C_d/C_{d−1})|, trading days only. Done when: file and manifest exist; the journal reports first and last date, number of days, days with a missing or non-positive close (excluded, counted).

    S1.3 GDELT, in chunks. scripts/extract_gdelt.py --from <cursor> --days N. Filter and dates as in amendments #16–#17. Outputs: data/events/gdelt/daily.csv (date, n) and data/events/gdelt/MANIFEST.json with, per day, files read, files missing (GDELT has gaps: 404 = missing, not zero), raw rows, rows passed. The cursor gdelt_cursor in STATE.json advances with every chunk. Done when: the cursor is past 2026-10-26. Days with more than 10% of files missing are listed in the journal and marked incomplete in the CSV; they stay in the analysis (excluding them afterwards would be a choice made on the data), but the report counts them.

    S2 — Phase 2a: marginal structure and power (no sky)¶

    S2.1 For each arm (GDELT, daily USGS, markets): mean, variance, negative binomial k (moments), autocorrelation up to 400 days, annual and weekly amplitude, φ of an AR(1) on the deseasonalised log-rate. On all days: looking at y without the sky is allowed (V9). Caution: GDELT has a strong secular drift (≈ 150–190 events/day in early 2015 against ≈ 27 in 2026 with the same thresholds): it must be measured and reproduced in the synthetic generator, because Phase 0 assumed ±30%. Output results/phase2a/marginals.json.

    S2.2 Synthetic generator per arm, with the parameters from S2.1 (structured NB counts for GDELT and USGS as in counts.ts; for markets an AR(1) log-volatility with seasonality, y = exp(·)·|ε|). Never real y in the simulations.

    S2.3 Power and calibration on synthetic y: Phase 0 for GDELT and USGS with the measured parameters; markets need the 340-year null (amendment #19: round(365.2425·j) + u), to be added to engine/src/mundane/surrogates.ts with tests, and a calibration on 400 pseudo-real windows. Done when: results/phase2a/ contains, per arm, calibration (false positives at 0.05 and 0.01) and the n=2 MDE per class. Gate: if the markets arm is not calibrated it leaves the primary analysis (this is declared; H1 and H2 stay on GDELT alone but the Bonferroni factors stay 8 and 2, which is conservative). If the Moon class on GDELT has MDE > MEI, the study stops and the report is written (protocol § 4.3).

    S2.4 (amendment #29, decided by the PO on 2026-10-29) GDELT calibration on the real counts: the S2.3 calibration with the real GDELT y of the exploration set in place of the synthetic one, exactly as amendment #29 specifies (400 windows on the frozen grid, none within 40 years of 2015-02-19, harmonic 2, primary filter, Tier 1 shifts, seed 20261029, summarizeCalibration unchanged). Run once. Done when: results/phase2a/calibration-gdelt-real.json exists and the journal applies the rule of #29: PASS → GDELT stays in H1/H2; FAIL → GDELT is descriptive, its H1/H2 sub-tests and H4 count as p = 1. Then S4.1 for GDELT and holm, then the rest of S4.2.

    S3 — Analysis code (TS, in the engine)¶

    S3.1 pnpm mundane analyze --arm <gdelt|usgs|markets> --set exploration --out <file>: reads the daily series, the split (data/split/months.csv) and protocol v0.4; builds the grid once; computes for H1 (harmonics 2,3,4,6; aggregate and three classes), H2 (orb bands, trend) and, for USGS, H3 (diurnal phase, topocentric Moon, circumpolar cases counted) the observed δ̂, the global time-shift null (same shift vector for all days) and the one-sided p. The days are those of the set; the shifts move the sky, not y.

    S3.2 Set guard. analyze refuses --set validation if study/UNSEAL-validation does not exist, and --set prospective if study/UNSEAL-prospective does not exist or the date is before 2027-04-27. Tests that check it.

    S3.3 Tests. On synthetic y: recovery of an injected effect (n=2, δ=0.02) within ±0.005; calibration under H0 on 50 windows; determinism (same seed → same JSON); numeric contract. Done when: the tests are green and scripts/check-contract.sh passes.

    S3.4 pnpm mundane holm --in <files> --out <file>: combines as in amendment #27.

    S4 — Phase 3: exploration set¶

    S4.1 analyze on the three arms, --set exploration. Then holm. Outputs in results/phase3/. The journal reports the table per hypothesis and per class, without adjectives.

    S4.2 Exploratory analyses, closed list (exploration only, BH-FDR across all of them together, labelled "exploratory"): E1 per pair (14 × 4 harmonics × 3 arms); E2 harmonic spectrum 1–12; E3 orb sensitivity curve 1/2/3/5/8; E4 Tier 2 surrogates with the Sun pairs; E5 robustness filters 365/180/90 computed within the set, block by block; E6 GDELT by Goldstein sign; E7 USGS by depth (< 70 km against ≥ 70 km). Nothing else. A new exploratory analysis is written in the journal before it is run, and it becomes a result only if it replicates on the prospective set.

    S5 — Phase 4: validation, once¶

    S5.1 Tag analysis-v1 on the commit of the code used in S4; then create study/UNSEAL-validation containing the SHA of the tag. S5.2 analyze --set validation on the three arms, holm, once. Outputs in results/phase4/. Done when: the results are committed. No re-runs, no corrections: if a bug emerges, it is documented as a post-freeze amendment and both numbers are reported.

    S6 — Waiting for the prospective set (until 2027-04-27)¶

    Once a month (first session of the month): extend GDELT, USGS and markets from 2026-10-01 to yesterday, same procedure as S1. Other sessions: freeze check, one "waiting for the prospective set" row in the index, end. Minimal consumption.

    S7 — Phase 5: prospective, once¶

    From 2027-04-27: tag analysis-v1 unchanged, study/UNSEAL-prospective, analyze --set prospective (historical 20% + all days from 2026-10-01), holm, once. Replication of the S4.2 exploratory analyses that had q < 0.05.

    S8 — Phase 6: report¶

    docs/REPORT.md: protocol, deviations, confirmatory results (validation and prospective), labelled exploratory results, limitations (protocol § 8 and SPEC V § 8.4), and the opening sentence on the status of the OSF deposit. STATE.json → stage = "done".
