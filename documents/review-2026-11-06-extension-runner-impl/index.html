    The two declared departures (workflow header, lines 6-7)¶

    • oracle added to the paths copied from origin/main (:39) and to the paths unstaged before the commit (:49): sound. The RFC's own guard list (R2.1 step 1) already names oracle, and both the wrapper (extend_s6.py:33) and the checker (check_extension.py:29) guard it; the RFC's draft checkout line (R2.11) omitted it, so once the data branch is older than main in oracle/ the guard would refuse every month. oracle is a tracked tree on origin/main (26 files, no .gitmodules), so the git checkout pathspec resolves and the step cannot fail on it.
    • A checker failure does not stop the commit (:47): sound, and needed. The checker exits non-zero only when it could not write (:131-132, :253-258) or crashes; the draft would then have committed nothing, and the month's MANIFEST-s6.json would never reach the branch, so the refusal of a second markets or USGS request (extend_s6.py:106-113, 176-181, which reads that manifest) would not hold on the next dispatch. With the departure, s6-work/ is committed whatever the checker did, and a missing CHECK file is visible as a warning and, to the researcher, as the absence of the file R2.12 step 1 requires before any merge. R2.5's line for check G ("nothing is committed … but the report") is not what the draft did either; the implemented behaviour is the one consistent with R2.9.

    No third departure from the RFC text was found beyond findings 1 (in effect), 3, 4 and 10 above.
