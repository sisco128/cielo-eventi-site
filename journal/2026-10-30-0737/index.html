    Decisions made (before running what depends on them)¶

    Written at 07:39 UTC, before any code or run of E5. E5 is exploratory (amendment #25), so none of this changes a confirmatory estimate; the choices follow charter § 4 (literal text first, then most conservative, then simplest).

    • What E5 is. Plan S4.2: "E5 robustness filters 365/180/90 computed within the set, block by block". Source of the filter role: protocol v0.3 § 4.2 (the high-pass filter is a declared robustness check of the primary estimator), HP_WINDOWS_ROBUSTNESS = [365, 180, 90] in study/protocol-v0.4.json. So E5 = the H1 aggregate estimator at the primary harmonics {2, 3, 4, 6}, with the high-pass filter applied to both y and the sky series, one test per harmonic × window: 12 tests per arm. No class split, no H2/H3 under filters (not named by the plan; adding them would widen the closed list).
    • Block. Amendment #24: "the filtered variants are computed within the set, monthly block by block". Read as: a block is a maximal run of consecutive calendar months that all belong to the set; the filter runs on each block separately and never reads across a gap (so never near a row of another set). The other reading (each single month is a block) would make all three windows identical (every window exceeds a month), so it cannot be what a list of three windows means. Exploration blocks are 1–8 months long (USGS era from 1990: 111 blocks; markets from 1928: 308 blocks), so: the 365 window is longer than every block and reduces to removing each block's mean (the oracle's rule window ≥ length → subtract the mean, highpass in statistics.ts); 180 does so on blocks of ≤ 6 months; 90 filters blocks longer than 3 months. This is a consequence of #22 + #24, reported as such, not changed.
    • Filter. The engine's highpass (centred moving average, odd kernel, reflect padding, mean removal when the window ≥ block length), unchanged, applied per block. Window counted in rows: calendar days for USGS (zero days are rows), trading days for markets, as Phase 2a applied hpApply(y, hp) to the markets rows.
    • Sky side. The same block-wise operator F is applied to the sky rows of every shift: for shift s, c_s = c at (row grid index + s), then F(c_s). Estimator as Phase 2a's RowProjection.deltaHat: δ̂_s = Σ F(y)·F(c_s) / (mean(y) · Σ F(c_s)²) · Var(c_0 raw rows). One-sided upper p = (1 + #{δ̂_s ≥ δ̂_0}) / (1 + n).
    • Null. The arm's own shifts as in analyze and E1–E3 (armShifts(arm, new Rng(SEED)), stream path 1): Tier 1 for USGS, the 340-year null for markets. Each arm run once; output results/phase3/exploratory/<arm>-e5.json.
    • No BH-FDR here: it is applied once at the end of S4.2.
